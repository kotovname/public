## Три подхода к установке Proxmox

### 1) ZFS (рекоммендуемый вариант)
- Когда уместно: быстрые SSD/NVMe, много RAM, желательно with ECC.
- Плюсы: снапшоты, репликация, самовосстановление, контроль целостности, компрессия.
- Минусы: ощутимые требования к памяти и качеству/скорости дисков; желательно отдельный SLOG для ускорения синхронных записей.

### 2) Аппаратный RAID + ext4 (самый простой вариант)
- Когда уместно: есть аппаратный контроллер
- Плюсы: минимальная сложность на уровне ОС, ext4 предсказуем и надёжен.
- Минусы: зависимость от конкретного RAID‑контроллера/формата; миграции сложнее, чем с mdadm/ZFS.

### 3) mdadm (RAID) + Debian → апгрейд до Proxmox (мой вариант)
- Когда уместно: хочется прозрачности софта, переносимости массивов и полного контроля.
- Плюсы: независимость от железа, гибкость, понятные процедуры восстановления.
- Минусы: больше ручной работы на этапе установки и отдельной установкой Proxmox.

## На практике (в общих чертах)
1. **Разметка дисков (GPT):** на каждом диске отдельный ESP/EFI (вне RAID), остальное — под RAID1 сделано с помощью sgdisk.
2. **Сборка RAID в mdadm:** создаётся массив с помощью mdadm из двух дисков /dev/disk/by-id/* с суперблоком --metadata=1.2 --name=kvm-raid1
3. **Установка Debian на mdadm‑том:** Использовался net-install-debian13.iso при установке вручную указал ESP на каждом диске и следил, чтобы загрузчик ставился на обе ESP, а LVM на kvm-raid1. При желании можно собрать RAID в установочнике.
4. **Базовая сеть:** завёл статический IP для будущего веб‑интерфейса Proxmox; убедился, что имя хоста и DNS‑запись согласованы. Для VM - dhcp
5. **Апдейт системы и ядра:** Обновил Debian 13, создал точки монтирования к дискам *.qcow, проверил RAID1 с помощью cat /proc/mdstat.
6. **Апгрейд до Proxmox:** (https://pve.proxmox.com/wiki/Install_Proxmox_VE_on_Debian_12_Bookworm).Установка пакетов, смена ядра
7. **Репозитории:** отключил enterprise‑репо (нет подписки), включил no‑subscription — для обновлений. Отключил уведомление о подписке в pveproxy
8. **Добавление ВМ:** веб‑интерфейс по https://<host>:8006, добавление /srv/* как storage, создание vmbr1, vmbr2 (мосты) для VM, миграция *.qcow2 дисков в шаблоны VM через скрипт
